# 2.1.0 辅助类改名适配

## 问题与证据边界

用户提供的 issue.md 报告背屏中心 `RELEASE-1.0.2609231642` / versionCode `426092316` 更新后，原 `m2.g`、`C2.a` 被分配给其他类型；真正的传感器和定时器实现分别变为 `W1.g`、`o2.a`。报告称 DozeService 事件字段、方法以及两条策略保持不变，并附有拦截日志。

当前 2.0.0 源码确实按旧短名加载辅助类，因此报告描述与代码失效机制一致。本轮仅收到 issue.md，没有报告所提到的 patch 或新版 APK，未独立核验新版 DEX、报告里的设备日志或长时间暗光行为。不能将报告中的实测结论当成本轮验证。

## 实现

- 从稳定入口 `com.xiaomi.subscreencenter.doze.DozeService` 的实例字段 `k`、`j` 读取类型，不再加载字面短名 `m2.g`、`C2.a`。
- 确认 `k` 实现 SensorEventListener，`j` 实现 AlarmManager.OnAlarmListener，且为具体类；使用 Java 原生 `isAssignableFrom` 检查继承接口，无需自写递归遍历。
- `n` 必须与 `k` 类型完全一致，`q` 必须与 `j` 类型完全一致；保留构造器、字段、方法参数与 void 返回值的严格校验，并拒绝错误的静态成员。
- 将解析逻辑提取为独立的 RearScreenProfile，便于直接测试，不依赖或实例化 XposedModule、DozeService 或回调对象。
- 安装日志增加实际 `sensorListener` / `alarmListener` 类名，不再固定显示旧固件型号。未知结构仍在安装 Hook 前拒绝，模块继续走原有失败透传流程。

仍依赖 DozeService 入口、事件字段、分支含义和方法结构；不是对未来所有混淆或固件的通配适配。没有扫描整个 DEX、猜测多个短名、放宽到全局电源 Hook 或忽略类型校验。

## 不变项

Root 亮度、AOD、永不息屏、C 守护、配置通道、传感器筛选、暗光专属计时器和失败透传流程不变。结构解析仅在目标进程加载时进行，不新增常驻服务、线程、轮询、Root 命令或唤醒锁。运行中的传感器处理路径没有增加结构查找。

versionName `2.1.0`，versionCode `25`，沿用现有发布签名。正式包名调整为 `top.rongshangs.brightnesslock`；此前同版本旧包名测试包不能覆盖此包。迁移时先在旧版恢复系统控制并关闭、停用旧 LSP 模块，再卸载旧版、安装新包并重新授权、配置。源码仓库保留 RongShangs/bright，模块分发另行申请收录。

## 验证

新增合成结构测试覆盖：旧布局、改名布局、继承接口、无关 DeathRecipient、两类回调不一致、两个定时器类型不一致、构造器错误、owner 错误、返回值错误、静态字段、入口/字段缺失和抽象实现。

辅助类适配阶段的旧包名测试包通过了 37 项 JVM 单元测试和 15 项原生解析/边界检查；该包已被后续正式包名与切页动画构建取代。最终发布检查见 [2.1.0 Release 记录](releases/v2.1.0.md)。当前 ADB 未连接设备，未进行本轮真机测试。

合成结构测试不能代替原版与新版厂商 APK 的真机回归。两版均需确认：

1. 覆盖安装测试包后重新加载背屏中心中的模块代码；普通用户可重启手机。本轮不自动强制停止系统应用、不清空日志。
2. 保存安装日志，确认实际实现类、配置掩码和拦截日志，无 Unsupported / failed；新版预期为 `W1.g` / `o2.a`，旧版预期为 `m2.g` / `C2.a`。
3. 在 AOD 中分别测试遮挡、立即暗光、暗处超过 6 分钟，以及关闭开关后的系统行为恢复。
4. 确认 Root 基础功能、主屏通话感应、正常手动息屏和其他超时未被扩大拦截。
