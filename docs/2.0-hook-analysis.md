## 两条实际策略

所有目标位于 `com.xiaomi.subscreencenter.doze.DozeService`，它是背屏 AOD 的 DreamService，不是主屏全局电源策略。

| 策略 | 实际事件与动作 | 拦截范围 |
|---|---|---|
| 遮挡 | `m2.g` 分支 0，vendor non-UI 传感器 `33171227`，值 >= 1 时记录 pocket，并设背屏 OFF | 仅跳过这个 near 分支；值 0 的 away/恢复路径保留 |
| 暗光立即息屏 | 同一监听器分支 1，vendor 传感器 `33171129`，事件码 1/2 设 OFF、标记低光 | 仅跳过低光事件码 1/2 |
| 暗光延迟息屏 | 事件码 3 安排 `300000ms` 定时器，tag 为 `SubScreenOffAlarmTimeout` | 跳过事件码 3；拦截专属定时器的安排及触发；开启时取消已安排的旧定时器 |
| 环境恢复 | 暗光事件码 4/5 清除低光标记，条件满足时回到 DOZE_SUSPEND | 保留 |
| 解锁后超时 | 同服务的另一计时器 `SubScreenAutoOffAlarmTimeout`，90000ms | 保留，不受两个新开关影响 |

因此本固件为 **5 分钟暗光延迟**。不能因为旧描述写“三分钟”，就 Hook 任意 180000 常量。`AntiburnScreenController` 中的三分钟涉及主屏视频防烧屏，与本功能无关。

## 实现与低占用边界

- 使用 libxposed API `101.0.1`（compileOnly）和 service `101.0.0`。作用域仅背屏中心，不注入 system_server / SystemUI。
- 模块先检查类、构造器、字段类型与方法签名；全部 Hook 安装成功前保持透传。失败时移除已装 Hook、记录日志并保留原行为。
- 两个布尔配置存于 LSP 的远程配置组 `rear_screen_policy_v2`，App 写入、目标进程只读。目标进程监听配置变化并缓存位掩码；每次传感器事件不发 Binder 请求、不读文件。
- 目标进程只复用系统现有回调，不新增 Service、循环、线程、Root 命令或 WakeLock。关闭两项时传感器 Hook 快速透传。
- 开启时在 DozeService 原有 Handler 上取消旧暗光定时器、清除对应策略标记。不主动点亮已关闭背屏，避免覆盖正常手动息屏。
- 关闭时让后续系统事件恢复正常；不伪造传感器读数、不强制重启系统服务。如需立即完整刷新原有传感器状态，重新唤醒背屏。
- 原有 C 守护及其轮询频率未更改。只调亮度、不用永不息屏时，仍不增加显示查询或唤醒锁。
- App 配置通道不取得退出门禁持有权。面板关闭且控制操作完成后仍按已有退出流程自杀；仅由配置 Provider 拉起、无页面/磁贴绑定时也安排空闲退出。
- “恢复系统控制”同时尝试关闭两个 LSP 开关。Root 恢复与 LSP 保存分别确认；LSP 不可用且存在开启/不确定状态时，明确提示未全部恢复。
- 主面板保留原有 220dp 高度，右侧黄色“背屏策略”进入二级页面；永不息屏与两个 LSP 开关按 Root / LSP 分组，左侧旧入口移除。二级页面可滚动，返回按钮/返回键回到主面板，点击空白关闭整个面板。编辑策略时暂停原有亮度刷新，返回主面板再恢复。
- “LSP 配置通道已连接”表示配置通道与作用域检查通过，不是 Hook 已在真机生效的确认。
- 这不是“无功耗”：LSP 本身有注入开销，背屏少息屏也会增加显示耗电和烧屏风险。未提供新的 CPU、内存、待机电量保证。

## 不做的改动

- 不拦截通用 `goToSleepSecondaryDisplay` 或所有 `setDozeScreenState(OFF)`。
- 不屏蔽主屏距离/光线传感器，不改通话贴耳息屏。
- 不改电源键、双击、热保护、解锁 90 秒超时或厂商其他保护路径。
- 不把 AOD 强行变成活跃画面；需要活跃展示时仍使用原有“永不息屏”，其功耗和边界不变。
- 不以轮询唤醒替代这两个 Hook，不自动安装/启用 LSP 或修改作用域。
