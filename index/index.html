轻巧，选择更自由

Root 管亮度与活跃显示，LSP 管 AOD 的指定省电策略。各自独立，按需启用。

01

亮度控制

手动亮度最低为 10；正常每 4 秒读取背光节点校正，仅调亮度不查询显示状态或持有唤醒锁。

02

Root 活跃显示

永不息屏移至“背屏策略”，复用原有 C 守护检测息屏并尝试唤醒。不依赖 LSP，可能短暂黑屏。

03

LSP AOD 策略

分别阻止背屏 AOD 的暗光和遮挡自动息屏，不强制变为活跃画面，不干涉主屏通话感应。

04

紧凑玻璃面板

主面板保持原有比例，右侧黄色入口打开分组策略页；横屏可滚动，颜色跟随系统深浅色。

05

按事件处理

LSP 只在已有背屏中心的相关回调中判断，不新建服务、循环、线程或唤醒锁。

06

干净退出

面板关闭、操作完成后主动退出 App 主进程；恢复系统控制同时停止 C，并尝试关闭两项 LSP 策略。

Quick start

四步开始使用

安装并授权

v1.6 及以上可覆盖安装。授予悬浮窗与 Root 权限，拖动亮度即可使用基础功能。

打开背屏策略

右侧黄色入口进入策略页。Root 分组的永不息屏无需安装 LSP。

按需启用 LSP

需要 AOD 拦截时，启用支持 API 101 的 LSPosed，作用域仅选“背屏中心” com.xiaomi.subscreencenter。首次启用或更新模块后重启。

随时恢复

“恢复系统控制”停止 C、恢复超时并尝试关闭 LSP 两项。卸载前先关闭策略并恢复。

FAQ

常见问题

支持哪些设备？

基础 Root 功能面向小米 17 Pro / Pro Max、HyperOS 3 / 4。新 LSP 功能已在 pandora、OS4.0.0.41.XBLCNXM、Android 17、LSPosed 2.2.0 (7854) 上获得拦截日志并由用户确认正常；其他固件未验证，不匹配时保留系统原行为。

一定要装 LSP 吗？

不用。亮度、AOD 和永不息屏仍只需 Root；只有阻止 AOD 暗光、遮挡息屏两项需要支持 API 101 与远程配置的 LSPosed。不要把模块作用域选为系统框架或全部应用。

LSP 拦截和永不息屏有什么不同？

LSP 两项仅拦截 AOD 的指定省电策略，不主动唤醒，不影响主屏通话感应、电源键、双击、热保护或其他超时。Root 永不息屏复用 C 检测息屏后尝试唤醒，保持活跃画面，开销更高且可能短暂黑屏。

更新后开关保存了却没效果？

已加载的模块不会因覆盖安装 APK 自动换成新代码。首次启用或更新模块后请重启手机，再打开背屏策略。仅切换开关无需重启；已息屏时请先唤醒背屏。连接状态不代表对其他固件的适配保证。

为什么旧版不能覆盖安装？

v2.0.0 沿用 v1.6 起的证书，可覆盖 v1.6 及以上版本。v1.5 及更早版本需先恢复系统控制、卸载旧版后安装。2.0 测试版用户也可直接覆盖。

恢复后还有后台吗？

恢复会停止 C、尝试关闭 LSP 两项。操作完成、面板关闭后主进程主动退出；系统仍绑定磁贴时暂缓退出。LSP 复用已有背屏中心，不新增常驻服务或轮询。

会增加耗电或烧屏吗？

只调亮度的机制与 v1.8.0 一致：正常每 4 秒检查，不查询显示状态、不持有唤醒锁。永不息屏有额外唤醒开销；LSP 虽无新轮询，减少息屏本身仍增加屏幕耗电与烧屏风险。暂无真实功耗数字保证。

应用会联网吗？

控制与配置逻辑全部本地完成，不上传设备或使用数据。打开网页链接会交给外部浏览器。
